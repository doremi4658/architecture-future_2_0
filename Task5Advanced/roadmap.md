## 3. Стратегический роадмап внедрения Data Mesh (`roadmap.md`)

Роадмап увязан с тремя фазами, обозначенными в кейсе «Будущее 2.0», и дополнен ролями, необходимыми для каждого этапа.

### Фаза 1 — Пилот (0–6 месяцев)

**Бизнес-цели:**  
- Проверить жизнеспособность Data Mesh и событийного подхода.  
- Запустить витрину самообслуживания для одного бизнес-направления (например, «Пациентский поток»).  
- Минимизировать риски, отработать контракты.

**Ключевые роли и ответственность:**

| Роль | Обязанности на этапе |
|------|----------------------|
| Data Product Owner (от домена «Медицина») | Определяет критерии качества данных, согласовывает схему первого Data Product (поток пациентов) |
| Data Engineers (2 чел.) | Разворачивают Kafka, Schema Registry, Flink; строят пайплайн от источника до витрины |
| BI-аналитик | Описывает требования к отчётам, участвует в приёмке пилотной витрины |
| Cloud Architect | Проектирует шаблоны инфраструктуры, настраивает CI/CD |
| Security Officer | Аудирует безопасность публикации медицинских событий без нарушения регуляторных норм |

**Артефакты:** событийные контракты, пилотные топики, первый Data Product в каталоге, метрики качества.

### Фаза 2 — Масштабирование (6–18 месяцев)

**Бизнес-цели:**  
- Подключить критически важные домены (Финтех, ИИ).  
- Перевести основных потребителей отчётов на Self‑Service Portal.  
- Организовать управление жизненным циклом Data Products.

**Новые / усиленные роли:**

| Роль | Дополнительные обязанности |
|------|-----------------------------|
| Data Product Owner (Финтех, ИИ) | Формируют доменные дата-продукты, отвечают за SLA и документацию |
| Data Engineers (+2) | Масштабируют пайплайны, внедряют антикоррупционные слои для легаси |
| Community Manager / Data Governance Lead | Внедряет стандарты качества, проводит регулярные ревью Data Products |
| BI-аналитики (4+) | Переходят на самостоятельное конструирование отчётов, больше не зависят от DWH |
| Platform Team Lead | Координирует развитие инфраструктуры, проводит обучение команд |

### Фаза 3 — Поддержка и эволюция (18–36 месяцев)

**Бизнес-цели:**  
- Завершить вывод легаси-систем из эксплуатации.  
- Достигнуть целевого состояния: все домены взаимодействуют через события, пользователи работают исключительно с порталом.  
- Выход на новые регионы и направления.

**Целевая структура ролей:**

| Роль | Ключевая деятельность |
|------|------------------------|
| Data Product Owners (на каждый домен) | Отвечают за стратегию данных в своём бизнес-подразделении |
| Data Engineers (встроены в домены) | Разрабатывают и поддерживают дата-продукты |
| BI-аналитики (встроены в бизнес-команды) | Непосредственно создают ценность из данных |
| Data Platform Engineering Team (центральная) | Развивает Event Hub, Storage, Catalog, предоставляет Self‑Service инструменты |
| Data Security & Compliance Officer | Непрерывный контроль соблюдения регуляторных требований |

**Критерии успеха через 3 года:**

- Количество Data Products в каталоге > 15.
- Доля пользователей, полностью перешедших на Self‑Service Portal — не менее 90%.
- Время от идеи отчёта до его готовности — не более 1 дня.
- Эксплуатационные затраты (TCO) снижены на 70% относительно исходных.

Роадмап может корректироваться по итогам пилота и обратной связи, но сохраняет стратегическую цель: слабосвязанная событийная платформа с доменным владением данными.
